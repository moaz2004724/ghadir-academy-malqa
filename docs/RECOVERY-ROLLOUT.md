# حماية واسترجاع بيانات الأكاديمية

## ما تم تنفيذه

- مركز «إنقاذ البيانات» متاح قبل الدخول وبعده. يقرأ فقط مفاتيح بيانات الأكاديمية المعروفة في localStorage وsessionStorage على الرابط الحالي.
- تنشأ نسخة مستقلة قبل تشغيل React وتسجيل الدخول. لا تُحذف المفاتيح القديمة، ولا يُستبدل أرشيف سابق، ويظهر تحذير إذا امتلأت المساحة.
- تصدير روابط الفروع القديمة عبر أداة مفضلة أو كود مستقل، ثم فتح JSON في المركز. الأداة تعمل على الرابط والجهاز المفتوحين فقط، ولا تقرأ تخزين أي نطاق آخر. لا تستخرج IndexedDB أو ذاكرة React أو كاش صفحات HTTP؛ النسخ المعروفة لهذا المشروع كانت تستخدم Web Storage.
- الأرشيف يستبعد كلمات المرور ورموز الدخول، ويحتفظ بالسجلات وروابطها ومصدرها. الأصول تبقى كما هي.
- حفظ الأرشيف على السيرفر وإعادة تنزيله للإدارة فقط. لا دمج تلقائي مع اللاعبين أو المدفوعات. المصدر الموجود بالملف غير موثوق ويجب مراجعته. التكرار في رفع نفس المحتوى لا ينشئ أرشيفًا جديدًا.
- تؤرشف نسخ الرابط الحالي تلقائيًا بعد دخول الإدارة. ملفات الروابط الأخرى تتطلب اختيارًا وتأكيدًا داخل الأداة. فشل الأرشفة يترك النسخة المحلية ويُظهر الحالة.
- قبل إرسال أي كتابة تشغيلية تُحفظ نسخة من الطلب محليًا. النجاح يتطلب رد JSON مؤكدًا، والطلبات غير المؤكدة قابلة للتنزيل. لا توجد إعادة إرسال تلقائية: فقدان الرد لا يعني أن الحفظ فشل.
- القراءة والكتابة عبر /api لنفس أصل الموقع. Vercel يوجّه المسار إلى Railway، وVite يوجّهه محليًا إلى localhost:3001.
- حضور المدربين أصبح محفوظًا بجدول مستقل. أُلغيت إعادة تهيئة البيانات وتغيير كلمات المرور والأسعار عند تشغيل السيرفر.

## قيود مهمة

- لا يمكن ضمان إنقاذ بيانات جهاز غير متاح، أو بيانات مُسحت بالفعل، أو بيانات لم تغادر ذاكرة صفحة قديمة مفتوحة. لا تُحدّث هذه الصفحة قبل تصدير ما يمكن تصديره.
- رفع ملف إلى «أرشيف السيرفر» لا يستورد سجلاته إلى جداول التشغيل. الدمج يحتاج مراجعة الفرع، التكرار، العلاقات والتعارضات على نسخة اختبار أولًا.
- الطلبات غير المؤكدة قد تكون حُفظت فعلًا. قارِنها بالسيرفر قبل أي إعادة إدخال، خصوصًا المدفوعات. تعطل التخزين المحلي يمنع الكتابة الجديدة بدل إرسال طلب بلا نسخة حماية.
- حفظ قاعدة البيانات لا يحمي ما لم يصل إليها. احتفظ بنسخ المتصفحات أيضًا.

## النشر عبر المستودع الحالي

- أمر التشغيل في railway.json أصبح تشغيل Node فقط، سواء كان جذر الخدمة هو المستودع أو backend. لا يوجد db push أو reset أو seed في مسار التشغيل.
- backend/prepare-schema.js يضيف جدولَي RecoverySnapshot وCoachAttendance وفهارسهما قبل استقبال الطلبات. يقبل CREATE TABLE/INDEX IF NOT EXISTS فقط، ويستخدم قفل معاملة لمنع تعارض تشغيل أكثر من نسخة. لا يغيّر جداول التشغيل أو سجلاتها.
- تجهيز الجداول متكرر بأمان. إذا كانت جداول بنفس الأسماء ذات هيكل غير متوافق، يتوقف تشغيل النسخة الجديدة بدل تعديلها تلقائيًا. Railway يتحقق من /api/health قبل تحويل المرور.
- إصدار الباك إند المتوقع في /api/health هو storage-recovery-v1. تظل الواجهة على رابط Vercel نفسه، وتوجّه /api إلى خدمة Railway الحالية.
- هذا النشر لا ينتظر سحب بيانات المتصفحات أو تنزيل نسخة من الإنتاج. لم يُنفّذ سحب بيانات إنتاج ضمن هذا المسار. خيار الإنقاذ وحماية الأصول المحلية يظلان متاحين.
- برنامج backend/backup.js موجود للاستخدام المنفصل عند توفر وصول الإنتاج. يُخرج نسخة JSON خاصة لكل الجداول ضمن معاملة قراءة فقط متسقة، مع أعداد السجلات وبصمة SHA-256. تحقق الملف لا يُغني عن اختبار الاستعادة.
- راجع بعد النشر تحميل الواجهة وإصدار الباك إند وصلاحيات الأرشيف. اختُبر إنشاء لاعب ودفعة وقراءتهما من جلستين مستقلتين على قاعدة اختبار محلية، دون تسجيل معاملات تجريبية على الإنتاج.

- node --test tests/recovery.test.mjs tests/recovery-routes.test.mjs
- npx prisma validate من backend
- اختبار PostgreSQL الحقيقي اختياري عبر RECOVERY_TEST_DATABASE_URL مع tests/database-integration.test.mjs. يقبل فقط قاعدة محلية اسمها ghadir_recovery_test ويشغّل الباك إند على 4319. لا يُوجّه إلى الإنتاج.

ملفات الاختبار تحتوي على بيانات وهمية فقط. ملفات backups و*.dump مستبعدة من Git. لا ترفع النسخ الاحتياطية أو أسرار Railway إلى المستودع.
